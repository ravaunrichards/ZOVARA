# ZOVARA Inbox and Creator Studio

This document describes the private messaging, calling, and media publishing implementation.

## Private inbox data model

The inbox uses the existing conversations, conversation_members, messages, message_receipts, call_sessions, call_participants, profiles, blocks, and account_settings schema, with these additions:

- conversation_preferences: per-member pin, mute, and archive settings.
- message_reactions: per-member emoji reactions.
- content_drafts: account-owned caption, audience, media references, and creation metadata.
- account_settings: message, call, group-invite, media-message, voice-message, typing, online-status, and read-receipt controls.
- call_sessions: ring expiry, end reason, and duration fields.

All private message and call data is protected by authenticated row-level policies. Conversation membership is created through validated database functions; clients cannot self-add to an arbitrary conversation. Group creation validates participant existence, block relationships, and recipient group-invite preferences.

## Realtime and calling

Private Realtime topics are:

- conversation:<conversation UUID> — message events, typing events, reactions, and participant presence. A user may subscribe or send only while an active member of that conversation.
- user:<profile UUID> — personal call invitation/state events and the account's own presence channel.

Realtime is used for immediate updates. The inbox keeps a short polling fallback for incoming calls and message threads when a channel disconnects.

Voice and video calls use the existing LiveKit token issuer. Tokens are generated by the API after database membership and call-policy checks; the browser never receives the API secret. Call rooms are limited to eight participants. Calls ring for 45 seconds, support accept/decline/leave/end, and the service-only expiry function marks unanswered invitations missed and removes stale rooms. Audio/video track controls and screen sharing are available in the call overlay.

These controls are authenticated and private; this implementation does not claim end-to-end encryption of message content or media tracks.

## API routes

| Route | Purpose |
|---|---|
| GET /api/v1/conversations | List the signed-in member's conversations and personal preferences |
| POST /api/v1/conversations/direct | Create or retrieve a policy-checked direct conversation |
| POST /api/v1/conversations | Create a policy-checked group conversation |
| GET /api/v1/conversations/:id/messages | Read messages, sender details, reactions, and receipt states |
| POST /api/v1/conversations/:id/messages | Send an idempotent text/media/voice message |
| PATCH /api/v1/messages/:id | Edit an eligible message |
| DELETE /api/v1/messages/:id | Delete an eligible message |
| POST / DELETE /api/v1/messages/:id/reactions | Add or remove a supported reaction |
| PATCH /api/v1/conversations/:id/preferences | Pin, mute, or archive a conversation |
| GET /api/v1/conversations/:id/calls | Read call history as a conversation member |
| POST /api/v1/conversations/:id/calls | Start a voice/video call and receive a participant token |
| GET /api/v1/calls/incoming | Receive active ringing invitations |
| POST /api/v1/calls/:id/decision | Accept, decline, leave, or end a call |
| GET / PATCH /api/v1/me/settings | Read and update per-account messaging/call privacy |
| GET / POST /api/v1/drafts | Read or save creator drafts |
| PATCH / DELETE /api/v1/drafts/:id | Update or remove an account-owned draft |
| POST /api/v1/media/complete | Register a verified private upload as a media asset |
| GET /api/v1/media/view-url?id=:id | Create a short-lived signed media URL after RLS authorizes access |
| POST /api/v1/posts | Atomically publish a post with up to ten owned media assets and creation options |

## Creator Studio

The web creator supports photo carousel selection and camera capture, video uploads and camera recording, text-only posts, preview filters, stickers, overlays, playback-speed metadata, captions, hashtags, audience selection, comments, and duet/stitch/download preferences. Drafts are stored per account and reference private uploaded media. Publishing is performed by a transaction-backed database function that validates media ownership and writes the post and its media links together.

The browser stores only temporary local media previews. Uploaded originals are stored in the private media bucket. The API signs media URLs only after the database returns an asset row visible under the requesting account's policies.

## Required runtime configuration and verification

Calling requires valid server-side LiveKit URL/key/secret values and an accessible LiveKit endpoint. Realtime messaging requires the configured Supabase public URL/anon key and authenticated session token. Media upload and view require the private media bucket and the API's server-side storage signing credentials.

A schema migration being applied does not prove that these runtime credentials or the deployed API are correct. Verify calls with two signed-in test accounts, verify private-channel denial for a nonmember, verify message/receipt visibility under two accounts, and test actual camera/microphone permissions on the target browser/device before production release.
