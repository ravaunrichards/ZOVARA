# Security Policy

Do not file exploitable security issues publicly. Send a private report to the designated
security contact configured by the repository owner. Until a contact is configured,
open a private security advisory in the hosting platform. Include impact, affected
version, reproduction steps, and a proposed mitigation when safe to provide.

Never include credentials, tokens, payment data, or private user data in issues. Rotate
any secret that may have been exposed. Production deployment requires HTTPS, managed
secret storage, restricted database access, backups, logging, and regular dependency scans.
